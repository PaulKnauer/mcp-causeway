- (decision) REFRAME ACCEPTED: mcp-causeway is a PUBLICATION LAYER for already-HTTP MCP servers in the k3s cluster -- public reachability, publicly-trusted TLS, Authelia OIDC auth, Streamable HTTP conformance. mcp-proxy demoted from centerpiece to optional future stdio on-ramp.
- (decision) Reachability = real owned domain + Let's Encrypt via cert-manager DNS-01 (no inbound port needed for issuance), split-horizon DNS to keep LAN traffic local. Rejected: Cloudflare Tunnel (extra dependency, Cloudflare in request path), HTTP-01 + port-forward 443 (opens inbound before auth exists).
- (decision) Auth = Authelia OIDC as the MCP OAuth authorization server; MCP servers act as resource servers validating JWTs. Reuses already-deployed Authelia + Soniq's existing oidc_issuer/audience/jwks_uri/resource_url support. OPEN RISK: dynamic client registration support in Authelia vs what Claude/ChatGPT/Gemini connectors require.
- (override) Supersedes earlier decision 'MVP reach = LAN + Claude Desktop only'. New Gemini/ChatGPT requirement made LAN-only untenable; public reach + auth are now MVP.
- (change) RISK CONFIRMED on chosen auth path: Authelia does NOT support Dynamic Client Registration (RFC 7591) today -- roadmap only, needs an in-database client table. MCP spec says AS and clients SHOULD support DCR, and Claude/claude.ai/MCP SDKs commonly rely on it to self-register. Mitigation candidates: pre-registered static OIDC clients per vendor, a DCR shim in front of Authelia, or swapping AS (Zitadel/Keycloak). Must land as an Open Question with a named fallback.
- (event) MCP auth spec facts for FRs: servers MUST implement RFC 9728 Protected Resource Metadata -- 401 + WWW-Authenticate carrying resource_metadata URL whose doc lists authorization_servers. Soniq has oidc_resource_url (likely PRM-capable); mqtt-mcp and hindsight are bearer-token only and would need PRM emitted for them. Strong argument for a uniform OAuth-terminating gateway component in mcp-causeway.
